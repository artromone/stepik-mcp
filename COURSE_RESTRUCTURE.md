# Stepik course restructure — general playbook

> **Назначение:** воспроизводимый рецепт реорганизации **любого** раздела курса на Stepik.
> Подтяни этот файл в свежей сессии (`@COURSE_RESTRUCTURE.md`) и примени к нужному разделу —
> история диалога не нужна, всё ключевое здесь. Конкретные планы по разделам тут НЕ держим.

## Что вообще делаем
Для очередного раздела курса:
1. Разбить его уроки («Минимум / Основное / Дополнительное») на **тематические уроки-категории**
   (≤ ~16 задач в уроке — это нормально, дробить сильнее не нужно).
2. Задачи с **детерминированным однозначным выводом** перевести в авто-проверяемые
   (`string` + Python-чекер). Остальные оставить free-answer.

## Курс и доступ

## MCP-тулы (в stepik_mcp_server.py)
- `stepik_create_string_code_step(lesson_id, text_html, checker_code, position, cost)` — новый авто-шаг.
- `stepik_convert_step_to_string_code(step_source_id, checker_code, text_html=None)` — конверт шага на месте.
- Вызов из скрипта: `getattr(srv.<tool>, "fn", srv.<tool>)`.

## Факты API (проверены эмпирически)
- Авто-проверка = `block.name="string"`. Схема `block.source` строгая, **все поля обязательны**:
  `{code, use_re(bool), case_sensitive(bool), pattern(str), match_substring(bool)}`. Непустой `code` → код-проверка.
- **Перенести шаг между уроками через API нельзя** (смена `lesson` у step-source игнорируется) ⇒
  реорганизация = пересоздать в новом уроке + удалить старый ⇒ **история сабмишенов сбрасывается** (пользователь это принял).
- Конверт типа НА МЕСТЕ (PUT того же step-source) историю НЕ сбрасывает, но не перемещает.
- В этом курсе `step id == step-source id`.

## Стандартный чекер
```python
ANSWER = "<точный вывод программы; многострочный — через \n>"
def check(reply):
    import re
    def norm(s):
        m = re.search(r'Ответ:\s*(.*?)\s*(?:Мысли:|$)', s, re.S)
        if m:
            s = m.group(1)
        s = s.strip()
        s = re.sub(r'[ \t]+', ' ', s)
        s = re.sub(r'\s*\n\s*', '\n', s)
        return s
    return norm(reply) == norm(ANSWER)
def solve():
    return ANSWER
```

## ⚠️ Free-answer = инструкторская проверка (иначе «любой ответ верный»)
Голый `POST step-sources` с `free-answer` НЕ создаёт проверку — шаг становится «Любой ответ
будет верным» (ничего не попадает в очередь рецензирования). Нужна отдельная инструкция:
```python
ins = api("POST","instructions",{"instruction":{"step":STEP_ID,"min_reviews":1,"strategy_type":"instructor","text":""}})
iid = ins["instructions"][0]["id"]
api("POST","rubrics",{"rubric":{"instruction":iid,"text":".","cost":5,"position":1}})  # cost = макс. балл
```
Конвенция курса: `step.cost`(«Баллы за задачу»)=1, а рубрика проверки `cost`=5.
Тул `stepik_create_free_answer_step` теперь делает это сам (`instructor_review=True`, `review_max_score=5`).
При ПЕРЕСОЗДАНИИ free-answer всегда восстанавливать инструкцию вручную, если создавали не тулом.

## Стандартные настройки авто-шага
На каждом пересоздаваемом авто-шаге: `cost=1`, `has_submissions_restrictions=True`,
`max_submissions_count=5`, `is_solutions_unlocked=True` (= «обсуждать решения только после
правильного»), `solutions_unlocked_attempts=3`.
Free-answer шаги пересоздавать, копируя исходный `block` и эти же поля настроек из оригинала.

## Правила: convert vs keep
**CONVERT** (в авто-проверку) — есть детерминированный однозначный вывод (число / строка / массив),
**даже если задача дополнительно просит «как исправить / почему»** (проверяем вывод; объяснение — на самоконтроль).
**Ответ ОБЯЗАТЕЛЬНО сверить компилятором Go перед установкой.** Конвертить лучше НА МЕСТЕ
(`stepik_convert_step_to_string_code`) — сохраняет историю сабмишенов.

**KEEP (free-answer + инструкторская проверка):**
- порядок итерации по map недетерминирован / печатается адрес;
- вывод = panic / compile error (формулировка ответа у студентов плавает → авто-проверка ненадёжна);
- «напиши/реализуй функцию», чистое «объясни почему»;
- версионно-зависимое поведение (напр. `&v` в цикле до/после Go 1.22).

## ⚠️ Никаких подсказок/ответов в условиях
В тексте задачи НЕ должно быть: вписанных решений (`Ответ: func …`), выводов в комментариях
(`// 4, 6`, `// [10 1 2 3 …]`, `//panic`), блоков «Подсказка/Ключевые понятия/Ожидаемый вывод/
Что проверяется», показанного «исправления». Вырезать при миграции — и у авто-, и у ручных задач.
Примеры вход→выход у «напиши функцию» — это спецификация, НЕ спойлер, их оставлять.

## Безопасный порядок выполнения
1. `POST lessons` — создать новые уроки-категории; `POST units` (section=<целевой>) на временных позициях (11+).
2. Пересоздать каждую задачу в её категории (внутри категории — порядок по исходному id):
   - convert → `string` + чекер(ANSWER) + стандартные настройки;
   - keep → копия исходного `block` + исходные настройки.
3. Прогнать боевые сабмишены на все авто-шаги: `attempts` → `submissions` (reply `{"text":..,"files":[]}`),
   ждать статус ≠ `evaluation`. Проверить correct/wrong.
4. `PUT units/{id}` — расставить новые юниты на позиции 1..N; удалить старые юниты и уроки.

## Процедура для нового раздела (по шагам)
1. Найти section по названию (`GET courses/289649` → `sections`).
2. Выгрузить все уроки/шаги с полным текстом, прочитать.
3. Предложить категории (≤16/урок), показать пользователю, согласовать.
4. Разметить convert/keep; для convert извлечь код, прогнать `go run`, записать точный ANSWER.
5. Выполнить миграцию безопасным порядком; сверить сабмишенами.
6. Отметить раздел в «Прогрессе» ниже.
